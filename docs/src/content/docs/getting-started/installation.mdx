Blockbusterr is distributed as a Linux container for AMD64 and ARM64 systems. Use Docker directly, Docker Compose, or a container-management UI such as Unraid, TrueNAS SCALE, or Portainer.

<Aside type="caution" title="Keep it private">
Blockbusterr can use an optional owner token, but you should still keep port 9090 behind a trusted LAN, VPN, or HTTPS reverse proxy. The built-in owner boundary is not a multi-user identity system.
</Aside>

## Prerequisites

<CardGrid>
<Card title="Docker" icon="seti:docker">
Docker 20.10+ or Docker Desktop
</Card>
<Card title="Persistent storage" icon="laptop">
A writable host directory mounted at `/app/data`
</Card>
<Card title="Network" icon="star">
Access to at least one discovery provider (TMDB, Simkl, Trakt, or MDBList) and your delivery stack
</Card>
</CardGrid>

<Aside type="note" title="Trakt is optional">
Configure any one supported discovery provider: TMDB, Simkl, Trakt, or MDBList. You only need Trakt credentials for jobs that use Trakt as their source.
</Aside>

<Aside type="caution" title="Installing v2">
Use `ghcr.io/mahcks/blockbusterr:latest` to follow stable updates, or pin the immutable `ghcr.io/mahcks/blockbusterr:v2.0.0` image. Before upgrading from v1, back up the complete data directory and follow the [upgrade guide](/getting-started/upgrading-to-v2/).
</Aside>

<Aside type="tip" title="Using a NAS or container UI">
See [Deployment platforms](/getting-started/deployment-platforms/) for field-by-field Unraid, TrueNAS SCALE, and Portainer instructions.
</Aside>

## Installation Methods

<Tabs>
<TabItem label="Docker Run" icon="seti:docker">

**Quickest way to get started** - Single command deployment.

<Steps>

1. Pull the latest image:

   ```bash
   docker pull ghcr.io/mahcks/blockbusterr:latest
   ```

2. Run the container:

   ```bash
   docker run -d \
     --name blockbusterr \
     -p 9090:9090 \
     -v blockbusterr-data:/app/data \
     -e TZ=America/New_York \
     ghcr.io/mahcks/blockbusterr:latest
   ```

3. Access the web UI at `http://localhost:9090`

</Steps>

<Aside type="tip">
Use `docker logs blockbusterr -f` to view live logs and verify startup.
</Aside>

</TabItem>
<TabItem label="Docker Compose" icon="seti:yml">

**Best for production** - Easy management and restarts.

<Steps>

1. Create `compose.yaml`:

   ```yaml
   services:
     blockbusterr:
       image: ghcr.io/mahcks/blockbusterr:latest
       container_name: blockbusterr
       ports:
         - "9090:9090"
       volumes:
         - blockbusterr-data:/app/data
       environment:
         TZ: America/New_York
         # BLOCKBUSTERR_AUTH_TOKEN: replace-with-at-least-32-random-characters
       restart: unless-stopped

   volumes:
     blockbusterr-data:
   ```

2. Start the stack:

   ```bash
   docker compose up -d
   ```

3. View logs:

   ```bash
   docker compose logs -f blockbusterr
   ```

</Steps>

</TabItem>
<TabItem label="With Full Stack" icon="puzzle">

**Complete setup** - Blockbusterr + Radarr + Sonarr on the same network.

```yaml
networks:
  media:
    driver: bridge

services:
  blockbusterr:
    image: ghcr.io/mahcks/blockbusterr:latest
    container_name: blockbusterr
    networks:
      - media
    ports:
      - "9090:9090"
    volumes:
      - ./blockbusterr/data:/app/data
    environment:
      - TZ=America/New_York
    restart: unless-stopped
  
  radarr:
    image: linuxserver/radarr:latest
    container_name: radarr
    networks:
      - media
    ports:
      - "7878:7878"
    volumes:
      - ./radarr/config:/config
      - /path/to/movies:/movies
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=America/New_York
    restart: unless-stopped
  
  sonarr:
    image: linuxserver/sonarr:latest
    container_name: sonarr
    networks:
      - media
    ports:
      - "8989:8989"
    volumes:
      - ./sonarr/config:/config
      - /path/to/tv:/tv
    environment:
      - PUID=1000
      - PGID=1000
      - TZ=America/New_York
    restart: unless-stopped
```

<Aside type="caution">
When using container networking, use container names in URLs:
- Radarr: `http://radarr:7878`
- Sonarr: `http://sonarr:8989`
</Aside>

</TabItem>
<TabItem label="From Source" icon="github">

**For developers** - Build from source code.

<Steps>

1. Clone the repository:

   ```bash
   git clone https://github.com/mahcks/blockbusterr.git
   cd blockbusterr
   ```

2. Install dependencies:

   ```bash
   go mod download
   ```

3. Build the binary:

   ```bash
   make build
   ```

4. Run Blockbusterr:

   ```bash
   ./bin/blockbusterr
   ```

</Steps>

**Development mode with hot reload:**

```bash
make dev
```

</TabItem>
</Tabs>

## Environment Variables

Configure Blockbusterr behavior with environment variables:

| Variable | Default | Description |
|----------|---------|-------------|
| `CONFIG_PATH` | config search paths | Directory containing the config file |
| `DATA_DIR` | `./data` | Database directory |
| `DISABLE_UI` | `false` | Disable the web UI when set to `true`, `1`, or `yes` |
| `BLOCKBUSTERR_AUTH_TOKEN` | unset | Optional owner token (at least 32 characters); sign in with username `blockbusterr` |
| `BLOCKBUSTERR_DRY_RUN` | `false` | Evaluate jobs and record decisions without sending content to Radarr, Sonarr, Jellyseerr, or Seerr |
| `VERSION` | build metadata | Override displayed version metadata |
| `COMMIT` | build metadata | Override displayed commit metadata |
| `TZ` | `UTC` | Timezone for scheduling |

**Example with custom settings:**

```bash
docker run -d \
  --name blockbusterr \
  -p 8080:9090 \
  -e DATA_DIR=/app/data \
  -e TZ=Europe/London \
  -v $(pwd)/data:/app/data \
  ghcr.io/mahcks/blockbusterr:latest
```

## Health Check

Verify Blockbusterr is running correctly:

```bash
curl -u blockbusterr:$BLOCKBUSTERR_AUTH_TOKEN http://localhost:9090/v1/
```

Expected response:

```json
{
  "version": "2.0.0",
  "uptime": "1785518792000"
}
```

## Updating

<Tabs>
<TabItem label="Docker" icon="seti:docker">

```bash
docker pull ghcr.io/mahcks/blockbusterr:latest
docker stop blockbusterr
docker rm blockbusterr
# Then run the original docker run command
```

</TabItem>
<TabItem label="Docker Compose" icon="seti:yml">

```bash
docker compose pull blockbusterr
docker compose up -d blockbusterr
```

</TabItem>
<TabItem label="From source" icon="rocket">

Download the new release or pull the latest code:

```bash
git pull origin main
make build
./bin/blockbusterr
```

</TabItem>
</Tabs>

<Aside type="caution" title="Backup Before Updating">
Always backup your `data` directory before major version upgrades:

```bash
docker stop blockbusterr
docker run --rm \
  -v blockbusterr-data:/data:ro \
  -v "$PWD:/backup" \
  alpine tar -czf /backup/blockbusterr-data.tar.gz -C /data .
```
</Aside>

## Troubleshooting

<CardGrid>
<Card title="Port Already in Use" icon="warning">
Change the port mapping: `-p 8080:9090` (host:container)
</Card>
<Card title="Permission Denied" icon="error">
Ensure the data directory is owned and writable by the user running Blockbusterr.
</Card>
<Card title="Can't Connect to *arr" icon="puzzle">
Use container names if on same Docker network, not `localhost`
</Card>
<Card title="Database Locked" icon="laptop">
Only run one Blockbusterr instance per data directory
</Card>
</CardGrid>
